# Markato architecture

Markato uses AppKit and TextKit for editing, Comrak for Markdown structure and HTML, Ultralight for the preview, and KaTeX for equations. This document describes the implementation; see the [README](../README.md) for the application overview.

## Editing and preview

Use the standard File and Edit menus to open and save Markdown documents, undo, redo, cut, copy, and paste. Command-F searches the whole document. Command-G and Shift-Command-G navigate results. The persistent title-bar button or Control-Command-S toggles the outline sidebar, Option-Command-P toggles the preview, and Command-Plus and Command-Minus adjust font sizes.

The Format menu applies atomic Markdown source transformations for bold, italic, strikethrough, inline code, links, headings, lists, blockquotes, code blocks, rules, tables, and images. Inline commands wrap the selection or place the insertion point between new delimiters; invoking a wrapper around an already wrapped selection removes it. Shift-Command-K fills a link destination from a URL on the pasteboard. Insert Image opens a native file picker and writes a path relative to a saved document when possible. Every transformation is one named document undo transaction and preserves the file's newline convention.

The source owns document navigation. Vertical wheel and trackpad gestures over the preview navigate the source; tables and code scroll horizontally within the preview. Drag the divider to change pane widths. Source syntax remains literal, with colors, font traits, and heading sizes applied to it. Preview context menus offer copying and independent item inspection.

The collapsible leading sidebar is a renderer-independent navigation shell. It starts hidden and can be revealed from the title-bar button or View menu. Its outline is built from heading level, plain inline title, stable block ID, and source range published by the Comrak-backed `PreparedDocument`; it never scrapes the preview HTML. Ordinary edits do not rebuild the outline: the retained block tree lazily shifts the unchanged suffix, and the sidebar keeps its existing rows. Current source positions are resolved from stable block IDs only when selecting or activating a heading. A semantic heading change advances a separate outline generation and refreshes the hierarchy. Selecting a row reveals that source range through the same navigation path used by Find. `SidebarPane` owns only hierarchy, selection, and disclosure behavior. This separation leaves room for search-result and comment providers to publish their own labels and source targets without coupling those features to Markdown rendering or the preview DOM.

Tables and code blocks are rendered as complete semantic blocks. Table column widths do not depend on which source rows are visible. Comrak recognizes strikethrough, inline/display dollar delimiters, backslash parentheses/brackets and math fences; KaTeX typesets the recognized equations, including aligned expressions and matrices. Raw HTML is passed through to the preview instead of being displayed as escaped source; preview JavaScript remains disabled. Code spans and ordinary fences remain code. Local images are resolved by the HTML preview module; HTTP/HTTPS image URLs are passed to Ultralight. Fonts and styles are bundled for offline use.

Files use UTF-8 or UTF-16. Existing UTF-8 BOMs and CRLF conventions are preserved; new documents use UTF-8. Saving is explicit: edits remain unsaved until the user invokes Save, and AppKit supplies the native edited indicator and close confirmation. No application-drawn modified-state label is used.

## Storage and parsing

See [the scrolling algorithm and simplification review](../docs/scrolling-algorithm.md) for the human-readable design, invariants, and current behavior. The [Markato performance overview](../docs/performance.md) contains the end-to-end benchmarks against MacDown, MacDown 3000, and MacDown 2.0.

The source model is an immutable AVL tree of bounded UTF-16 chunks. Indexed edits and line lookup avoid whole-document copying. Snapshots retain shared nodes for parser jobs and saves.

The source editor retains the complete text while measuring exact TextKit geometry only for prepared and visible regions. A single AVL layout index combines those measured lines with estimated gaps in one stable global coordinate system. Navigation can use an estimate to reach a distant region, then replaces that region with native measurements without rebasing the document. Edits and syntax updates preserve unaffected measurements, and model-driven edits and undo update the retained attributed text instead of reloading it. TextKit owns native selection and clipboard operations; the document model owns undo transactions.

Comrak runs as a pure parse operation on a serial native worker: a transient source string goes in and independently owned block records come out; no complete input buffer or parser state survives the call. Rope UTF-16 units cross directly into Rust, where they become UTF-8 without an intermediate Swift String. A single local edit reparses its affected top-level blocks plus one unchanged guard block on each side, then the adapter splices the verified records into the retained document. Initial parsing, coalesced edits, reference-link documents, and edits whose effects cross a guard fall back to one complete parse. Each parse and formatter traversal produces HTML and source-style records together. KaTeX receives only parser-recognized equations. A sparse Unicode/line index converts Comrak byte positions to Cocoa UTF-16 positions. Unchanged block IDs follow recorded edits, including duplicate paragraphs, only when both source and resolved HTML match. Stale delivery is rejected by revision/request generation.

Foreground presentation asks `PreparedDocument` for roughly 24 viewports of cached semantic blocks around the source viewport. That prioritized frame appears first. Background completion measures small HTML windows and retains only numeric block strides in the application tree; Ultralight never receives the complete block list. Later scrolling within the runway is position lookup and paint, while crossing it atomically replaces the bounded window. Headings and standalone image tops define the piecewise-linear source-to-preview map, with document endpoints supplying boundary coordinates. Paragraphs, code blocks, and table rows do not add scrolling references; images align at their top. Actual content, typography and width changes rebuild the map from current measured positions.

Every content or layout update follows one presentation pipeline. An immutable request captures retained entries, document revision, font, asset directory, and pane width. `HTMLPreview` owns Ultralight configuration, bounded DOM reconciliation, CSS, assets, element measurement, input, links, selection copying, and bitmap presentation. It reuses section elements by stable block ID and returns geometry only after rendering on its dedicated thread. The controller keeps the calibrated global scroll map and atomically publishes the resulting viewport bitmap and geometry. Visible layout and scroll work have priority over short background measurement slices.

The first presentation mounts only the initial prioritized window. Background preparation fills the retained HTML cache, then bounded Ultralight slices complete the retained geometry. The visible window remains bounded and is replaced atomically when navigation crosses its runway.

Both panes share a `PreparedDocument` containing an AVL block sequence, an interval index of complete source-style records, measured source lines and measured preview heights under the same block IDs and source coordinates. Each native update returns a manifest identifying the unchanged prefix and suffix. The document splices only the changed middle, lazily shifts suffix coordinates and retains cached HTML, syntax, source measurements and preview heights on both sides. A local edit gets another prioritized frame first, followed by complete background geometry for the new revision.

The Comrak adapter preserves complete paragraphs, lists, quotes, tables and code across viewport changes. Source delimiter styling is derived from parser-recognized source ranges, rather than another Markdown parser. Initial and fallback parsing, the retained model, and complete background layout grow with document size. Foreground parsing and first presentation stay bounded by the affected region or priority window. The Ultralight module boundary is documented in [Ultralight preview architecture](ultralight-preview-architecture.md).
